# Member 2 Orders use cases

An Orders Manager uses the English control panel for the synthetic EUR 20.00 workshop. Each case starts with one active position, no fees and no refunds. Paid fixtures have one confirmed EUR 20.00 manual payment. The viewer token reads the same order code before and after each transition with `include_canceled_positions=true`, so the assertions can distinguish canceled positions from deleted or hidden rows.

## UC-03 · Retain a cancellation fee

Open the order, choose **Cancel order**, fill **Keep a cancellation fee of**, clear **Notify customer by email**, and choose **Yes, cancel order**. On success, check the confirmation and cancellation timestamp, the original position ID and its canceled flag, one cancellation fee, the new total, and the original payment and refund records. End at the refund prompt if it appears.

| ID | Initial fixture and input | Expected result |
| --- | --- | --- |
| M | Paid FEE02, retain EUR 19.99 | Paid, total and fee EUR 19.99. |
| A1 | Paid FEE03, retain EUR 20.00 | Paid, total and fee EUR 20.00. |
| A2 | Pending FEE04, retain EUR 5.00 | Pending, total and fee EUR 5.00 with zero payments. |
| E1 | Paid FEE05, enter EUR 20.01 | Fee-cap error on form. Original snapshot preserved. |
| E2 | Paid FEE06, enter EUR 5.001 | Precision error on form. Original snapshot preserved. |

UC-03 covers CAN-02/03 and BR-03/04, including the incorrect-fee, partial-write and ticket-eligibility risks R5–R7.

## UC-04 · Record payment and then cancel the same order

Choose **Mark as paid**, enter EUR 20.00, clear the email checkbox, and submit **Create payment**. Check the payment confirmation and read back exactly one confirmed manual payment, paid status, and the original total and positions. Use the UC-03 cancellation form on that order. Compare the payment identity, amount, date, positions, fees, total and refunds at the end. The HTML report includes sanitized before, paid and canceled snapshots for the three successful journeys.

| ID | Initial fixture and change | Expected result |
| --- | --- | --- |
| M | Pending FLW02, pay then leave fee empty | Canceled and dated. Keep total EUR 20.00, position flags and payment. |
| A1 | Pending FLW03, pay then retain EUR 5.00 | Paid and dated, total EUR 5.00, one fee and a canceled position. |
| A2 | Expired FLW04 with available quota and late payment enabled, pay then leave fee empty | Payment succeeds. Final state matches M. |
| E1 | Expired FLW05, last limited seat already held | Payment shows quota error. Order stays expired with one failed attempt. The flow stops at W1. |
| E2 | Pending FLW06, pay then enter EUR 20.01 | W1 persists. W2 shows fee-cap error and the paid snapshot is preserved. |

UC-04 covers PAY-01/02, CAN-01/02/03 and BR-01/03/04 across the same order, including inconsistent status, quota, fee and partial-write risks R2/3/5/6.

## Run on Windows

After the dependencies and assets in the Windows handoff are installed, stop the test server and run from the repository root

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File sqe/windows.ps1 reset
npm.cmd --prefix src/tests/team/e2e test -- uc03-uc04.spec.js
~~~

Run without the filename to include UC-01 and UC-02 on the same reset. The HTML report is in `local/sqe/evidence/playwright-report/index.html`. [Observed results](../member2-browser-results.md) · [Browser tests](../../src/tests/team/e2e/uc03-uc04.spec.js) · [Windows handoff](../handoff.md)
